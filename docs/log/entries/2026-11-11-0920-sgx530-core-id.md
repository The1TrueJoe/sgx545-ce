# SGX530: the core identifies itself

**Board:** our OMAP3630 test board (ARMv7 Cortex-A8), mainline 7.1.8, the GPU node
`50000000.gpu` (`"ti,omap3630-gpu", "img,powervr-sgx530"`) inside the ti-sysc module
`target-module@50000000`, unbound before the test.

**What ran:** powervr_sgx from sgx530 34c2d59, built by `powervr-sgx-omap3630` against the
board's own config with gcc 15.3, the board's compiler. The DRM helpers came from the same
build. The probe (`pvrsgx_of.c`) maps the first 16 KiB of the window, runtime-resumes the
ti-sysc parent, and reads only `CORE_ID` (0x0010) and `CORE_REVISION` (0x0014). The SGX530
family isn't usable yet (no event PDS registers), so the probe logs both and stops before
any write.

```
powervr_sgx 50000000.gpu: [drm] SGX530 core id 0x01120000 revision 0x00010205: this driver can't run an SGX530 yet; not touching it further
```

The same values came back on a second load. The parent was runtime-suspended before and
after, the kernel stayed untainted, and the five modules unloaded cleanly.

**Facts (tag C):** `CORE_ID` 0x01120000 (id 0x0112, config 0), `CORE_REVISION` 0x00010205
(1.2.5). The revision is the one derived from the binding's "rev 125" and ti-sysc's OMAP34xx
match. The id field was unknown.

**On the way:** the first attempt used modules built with Ubuntu's gcc 13. The board
refused the helpers ("disagrees about version of symbol dev_driver_string", ...): gcc 15
sets `CC_HAS_COUNTED_BY` and similar options, which change the genksyms CRCs even with the
same config. `powervr_sgx` was never inserted then, and no GPU register was read. CI now
uses gcc 15.3, and `drm/tools/modver-check.py` checks a module set's CRCs against the
board's own modules before a load: 0 of 240 shared symbols differed this time.
