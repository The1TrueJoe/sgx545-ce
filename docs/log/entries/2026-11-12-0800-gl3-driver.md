# GL 3 driver runs 4 and 5: gl_FragDepth (H10), sampled depth textures, the ARB_framebuffer_object cap

2026-11-12, the second CE5300 board, RAM boot of powervr_sgx's
wip/msaa4-kcalc 4249037c (uAPI rev 3), open microkernel eb484b2. The kernel
image, the four modules and `/proc/version` were checked against the build
artifact before each boot, and the normal boot was restored after each run.
Neither run had a GPU reset, page fault, WARN or BUG.

Mesa from claude/gl3-driver-850ecf:
- A = 257051fe: depth textures sampled from their ZLS buffer, and gl_FragDepth
  through depthf behind `SGX_DEBUG=fragdepth`.
- B = 5de10967: A plus `mixed_framebuffer_sizes`.
- F = a012e986: B plus depthf by default.

**Run 4** (A, B; 06:34-07:33Z):
- dEQP-GLES2 on A: 78 fail, 16638 pass, 0 differences from run 3.
- **H10**: `mesa/tests/sgx_fragdepth.c` without `SGX_DEBUG=fragdepth` fails
  as expected: every pixel stores 0.5. With it, all three cases are exact
  (8064/8064, worst depth error 0): a gl_FragCoord ramp, a varying ramp,
  and a discard with `(p1) depthf`. The ten piglit tests that write
  gl_FragDepth all pass with it; written into ISA.md.
- A's three piglit lists didn't run. The piglit tree trimmed for this
  board's 487M root lacked drive-deqp.py's canary test
  (`glsl-1.10/execution/glsl-fs-add-masked.shader_test`), so each list
  stopped at "the canary doesn't pass on a fresh box". The file was copied
  to the board mid-run for B's lists.
- B's `glsl-fs-flat-color` crashed because the trim also lacked
  `tests/shaders/glsl-color-mvp.vert`, which the test reads without naming
  it. `clipping@fixed-clip-enables` failed once; run 5 didn't reproduce it.

**Run 5** (F, A; 07:37-07:50Z). The trim now keeps every data directory of
piglit's `tests/` and the canary. The run checks the canary on the board
with a one-test list before the others, and stops if it fails.
- On F, against runs 2 and 3: no pass → fail in the depth/stencil gate
  (157 tests), the multisample list (156), the fixed-function list (117) or
  the GL 2.1 list (275). 17 fail → pass, 17 skip → pass, 10 new FBO depth
  passes. Details in docs/GL3.md, Status.
- `sgx_fragdepth` on F (no debug option): all three cases pass.
- A on the gate: the FBO depth tests give the same 5 failures as F
  (`tex1d` ×4, `fbo-depth-sample-compare`). `fbo-depthtex` and
  `fbo-alphatest-nocolor` pass without the cap too.
  `clipping@fixed-clip-enables` passes on A and F.

**deqp-runner 0.23.2 panic**:
- `src/lib.rs:1163`, `test_groups.multi.first().unwrap()` in
  `parallel_test`, panics when a chunk holds only tests with
  `run_concurrent=False`: there is no multi-threaded group. Run 3's gate list
  had a chunk of 20 single-threaded `depthstencil-default_fb` tests, and the
  rest of the list didn't run.
- Workaround: an interleaved caselist (`gl3d-2026-11-11/r4/zs-gate-mixed.txt`)
  that puts a concurrent test in every chunk. Not reported upstream.
