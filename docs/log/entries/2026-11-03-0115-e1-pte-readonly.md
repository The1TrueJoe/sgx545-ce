# E1: the MMU's READONLY bit stops a client shader's store, by a page fault

Experiment E1 of the shader-validator design (`docs/DRM-DRIVER.md` section 6, decision D9):
can a client's USSE task write a page mapped with the PTE `READONLY` bit (0x4)? The
validator only works if validated code pages cannot be rewritten by the GPU afterwards.

EA1, 2026-11-03 ~01:12 UTC, normal boot (DDK services, `pvrsrvkm`), panel web view
stopped, `/tmp/gpu.lock` held, `tools/iso/suite_e1.py`.

## Method

Two buffers in the general heap: `R` (read-write, results) and `B` (filled with
0x11111111 by the host). A fragment task stores 0xdeadbeef to `B`, loads `B` back, copies
the loaded value to `R` and outputs it as the pixel colour. The DDK maps an allocation with
READ and no WRITE attribute (0x9) with `READONLY` in its PTEs.

| test | `B` attributes | pixel (load-back) | host `B` | kernel log |
|---|---|---|---|---|
| `e1_st_rw_control` | read-write (0xf) | 0xdeadbeef | 0x11111111 | nothing |
| `e1_st_readonly` | read-only (0x9) | 0 | 0x11111111 | lockup, then **BIF fault at `B`**, HWR |

The read-only run's recovery dump:

```
EUR_CR_BIF_INT_STAT:     00080400
EUR_CR_BIF_FAULT:        3E19F043      (B is 0x3e19f000)
```

## Result

- **The store to a READONLY page faults and does not land.** The fault address is the
  buffer's page; the task's load-back returned 0, not the sentinel; the stalled requestor
  locked the core until the DDK's lockup timer ran one hardware recovery. The GPU recovered:
  the web view rendered again and no further lockup followed.
- The read-write control raised nothing, and its load-back returned the sentinel.
- **Caveat:** in the control the host did not see the store either (`B` and `R` both read
  back unchanged), presumably because the write-back data cache was not flushed before the
  host read. So "memory unchanged" is not evidence here; the fault and its address are.
- Bit 10 of the fault-request field (0x400) is the requestor that faulted. Which unit that
  is goes with G2.

## For D9

Code objects mapped READONLY cannot be rewritten by a client shader: the attempt costs the
job (fault, reset), which a client can cause anyway, and is not an escape. Still to test:
a PBE (render target) write into a READONLY page, the second half of E1.
