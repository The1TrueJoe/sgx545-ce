# The open microkernel's frame-40 hang is not ACTIVE_POWER

CE5300 board (ce5300-v2) RAM boots of 4c16e33, 2026-11-08 ~19:10-19:18 UTC. The open microkernel
is um-re 8158141, or open-ukernel's 162c0b5 without the idle ACTIVE_POWER raise. The
reproducer is the Mesa winsys test `sgx545_frame_test -n 600` (one context). Each run
is on a fresh boot, because after this hang the open microkernel never runs a job
again (M1-exit Bug B).

| driver | microkernel | result |
|---|---|---|
| 3d0604b (ACTIVE_POWER never acknowledged) | 8158141 | frame 40 times out: kernel CCB 83 issued, 82 consumed; host control int 0x2/0x0 |
| 4c16e33 (acknowledges ACTIVE_POWER, as the DDK's host does) | 8158141 | frame 40 times out, the same way; int 0x0/0x0 |
| 4c16e33, `job_timeout_ms=60000 runtime_pm=0` | 162c0b5 (no idle raise) | frame 40 hangs; the live state before any reset is in the shared notes (`m1-exit-8158141/m2-noidleap-frame40-live.txt`): CCB 83 written, 82 read, `EVENT_STATUS` 0x2, `BIF_FAULT` 0 |

sgxgen's frame test (`powervr_sgx_frame`) runs past frame 40 on the same image with
either driver. It stops at frame 91, but only because its own PDS ring fills.

The ninth TA kick after frame 39's goes unanswered: the doorbell arrives, and the
command is never read. The microkernel has to fix it. The driver keeps the
acknowledgment, which matches the DDK's host, and gains `job_timeout_ms`.
