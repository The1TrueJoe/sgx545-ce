# SGX530 stage 1, third attempt: none of the microkernel's code runs

**Board:** our OMAP3630 test board, mainline 7.3.3 plus the OMAP3 GPTIMER12 clocksource fix,
with the board's critical thermal trip at 105 °C. RAM-booted. The thermal zone was enabled:
80.0 °C before the load, 78.5 °C after.

**What ran:** one attempt, per [sgx530-stage1.md](../../porting/cores/sgx530-stage1.md).
- powervr_sgx from sgx530 12e4b3a7, built by `powervr-sgx-omap3630` run 43130712528.
  powervr-sgx and upstream were green on the same head. `modver-check.py`: 0 differing CRCs
  against this boot's own modules.
- The diagnostic microkernel `sgx530_diag`: image a2ee6a6d… (17208 B), file 845463a3…,
  crc 0x1fb64e42, event program at 0x02004340.
- Its event entry runs a ladder before `phas.i`. Each step needs fewer instruction forms
  than the next:
  1. `limm` + `str`: `EVENT_TIMER` = 0xa5a;
  2. the patched `limm` pair, then `limm` + `st.a.d`: ctlblk 0x28 = 0xd1a60001;
  3. `ldr CORE_ID` + `st.a.d`: ctlblk 0x18;
  4. heartbeat +1;
  5. `phas.i`, then the normal entry.

```
clocks on: clock status 0x00010000 event status 0x00000000 BIF req 0x0 int 0x0 timer 0x00000000
clocks on: OCP revision 0x40000000 sysconfig 0x00000028 debug config 0x80000000 status 0x023c0707
event PDS registers before any write: enable 0x00000000 base 0x00000000 data 0x00000000 0x00000000
event PDS base 0x0a68: wrote 0x02004340, read 0x02004340
before the kick: clock status 0x00010000 ... BIF req 0x0 int 0x0 timer 0x00000000
100 ms ... 500 ms after the kick: clock status 0x00110000 event status 0x00000000 BIF req 0x2 int 0x0 timer 0x00000000
(the OCP line is unchanged at every sample)
*ERROR* microkernel did not start (init status 0x0, event status 0x0; BIF int 0x0 fault 0x0 req 0x2)
microkernel: init 0x0 version 0x00000000 wait 0x0 timeouts 0 heartbeat 0
probe with driver powervr_sgx failed with error -110
```

All five modules unloaded and the ti-sysc parent runtime-suspended.

**Result: the ladder's "all 0" row.** `EVENT_TIMER` stays 0, so step 1 didn't happen. The
wait marker, the version and the heartbeat stay 0 too. So none of the microkernel's USSE
code ran: not even its first `limm` + `str`.

**Facts (C):**
- 0xa68 holds the written address again (0x02004340 this time).
- After the kick, the USE clocks are on for the whole 500 ms.
- `BIF_MEM_REQ_STAT.READS` is 2 at every sample: in the second attempt it went 2, 0, 2.
- No fault, no event bit.
- The OCP wrapper is unchanged and not stalled.
- A first-instruction register store from the microkernel never lands.

**What's left** (G): between the kick and the microkernel's first instruction.
- **The PDS event program**, under the SGX530's PDS data layout, or its DOUTU: the entry
  program was written to read only rows that both layouts agree on. Whether the 530's PDS
  runs it the way the 545's does is U.
- **The DOUTU's code address against `USE_CODE_BASE_15`** (kernel code heap base >> 7, DM
  3 at b24). The 530's field is 24 bits, with its unit U. If the USSE starts at another
  address, it fetches whatever is there.
- **The task never reaching the USSE.** The USE clock domain may be busy with the PDS
  itself, which has no clock field of its own on the SGX530.
- The no-`phas.i` variant wasn't run: it differs only after step 4, which never ran.

**Next**, needing the microkernel side and the owner:
- **The code address.** A PDS program can't store to memory: its outputs (DOUTA, DOUTD,
  DOUTI, DOUTT, DOUTU) all feed the USSE ([PDS.md](../../PDS.md)). So the next split is on
  the USSE side. One option is to vary `USE_CODE_BASE_15`'s unit and the DOUTU's code
  address, with copies of step 1 wherever a 4-byte, 16-byte or other unit would make the
  task start.
- **The entry program.** Another is to change the entry program's layout, so a different
  data layout on the 530 can't feed the DOUTU the wrong words.

Each is a new attempt, agreed with the board owner.
