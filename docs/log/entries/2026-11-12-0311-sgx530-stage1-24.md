# SGX530 stage 1, twenty-fourth attempt: code bases in 256-byte units, and the task leaves PDS_EXEC_BASE

**Board:** our OMAP3630 test board, openHC on the SD (7.3.3, the 02:16 build), up 12 min,
the owner-confirmed host key, the board lock held. 77 °C before, 75 °C after. No hang, no
plug cycle.

**What ran:** powervr_sgx from sgx530 fd97aabe (4089fd7f and a docs merge; CI: omap3630
43180179389, powervr-sgx 43180171538 and upstream 43180175512, all green; modver-check 0
differ), `allow_unisolated=1 code_base_pads=1 stage1_sweep=1`, with the landing-pad image
`sgx530_bases` (f7de7b95…). Part 2 writes 0xa74 = 0x208200.
- **The change:** the SGX530 now writes every code base in 256-byte units
  (`use_code_base_addr_shift` = 8, the SGX545's 7). That's the attempt-23 reading: the
  EDM's fetch is at (field << 8) & 0x0fffffff. Code base 15 is 0xec000, kernel code
  0x0ec00000 >> 8.
- **The variants:** the baseline (the fix), then two fallbacks: code base 15 = 0x1b0000 to
  pin the shift, and 0xec001, one unit in.

**Results:**

| # | Code base 15 field | `BIF_INT_STAT` | `BIF_FAULT` |
|---|---|---|---|
| 0 | 0xec000 (the fix) | 0x4004 | **0x08039000** |
| 1 | 0x1b0000 | 0x4004 | **0x0b000000** |
| 2 | 0xec001 | **0x4002** | 0x0fd79000 |

- Every fault recovered with the reset. `EVENT_TIMER` stayed 0: no ladder value. INIT_STATUS
  stayed 0, and version, wait and heartbeat stayed 0.
- The fault check: 0x4004 at 0x0e800000, recovered. -ETIMEDOUT, all five modules unloaded,
  the parent runtime-suspended.

**Facts (C):**
- **The shift is 8:** 0x1b0000 faults at exactly 0x0b000000. With attempt 23's three cells
  that makes four (fact sheet, "The USSE and its code base").
- **With code base 15 at kernel code >> 8, the EDM task's fault leaves `PDS_EXEC_BASE` for
  the first time,** to 0x08039000, requestor b2. Every start since attempt 18 had faulted at
  0x0d800000 (or 0x0d801000 with the page mapped).
- **The task still doesn't reach the ladder's `EVENT_TIMER` write.**
- **One unit in (0xec001, a start at 0x0ec00100) faults at 0x0fd79000 with requestor b1,**
  the requestor of F1's DOUTD read (attempt 18).

**What it suggests (G):**
- **The task now fetches from the kernel code heap, where the image is mapped, and runs into
  something at 0x08039000.** Requestor b2 is the one every code fetch has shown, so this may
  be a fetch of code at an address the image computes. That would be a branch target or a
  code-base-relative address the microkernel derives with the SGX545's units, or another
  SGX545 assumption in the image's first instructions. The microkernel session can map it
  against the image.
- **0xec001's b1 read fits the image running from mid-stream** and doing a data access.
