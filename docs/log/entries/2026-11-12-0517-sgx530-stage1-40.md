# SGX530 stage 1, fortieth attempt: the PA0 probe's DOUTU started a task at code base 0 (inconclusive)

**Board:** our OMAP3630 test board, openHC on the SD (7.3.3, the 02:16 build), up 1 h 32 min,
the owner-confirmed host key, the board lock held. 77 °C before. No hang, no plug cycle.

**What ran:** powervr_sgx from sgx530 5730ea81 (CI: omap3630 43197884794, powervr-sgx
43197875421 and upstream 43197880397, all green; modver-check 0 differ), `allow_unisolated=1
stage1_sweep=1`.
- **The image:** the microkernel session's `cores/sgx530_pa0.py` (its branch, 6bc5351e):
  `phas.i #0, #0`; `ld.a.d r3, pa0, #0`; a branch to itself. 32 bytes, sha256 d69730f4…, crc
  0xec28b139, packaged f59ce697…, both matching the microkernel session's.
- **The question:** no register write from the task lands (attempts 31-39). Is a primary
  attribute the PDS writes visible to the task?
- **The variants:**
  - the normal event program;
  - an event program with two data rows, row 0 = (0x0e850000, 0) and row 1 = the normal
    DOUTU's words. It runs `MOVS` → DOUTA (PA0 = 0x0e850000, ctrl 0, docs/PDS.md), `MOVS` →
    DOUTU, HALT, with 0x0a6c = 2. 0x0a70 stayed 6.

**Results:**

| Variant | 0x0a6c read | `BIF_INT_STAT` | `BIF_FAULT` |
|---|---|---|---|
| normal event program | 0x1 | 0x4002 (b1) | 0x0f2d9000 |
| DOUTA to PA0, two data rows | 0x2 | **0x4004 (b2)** | **0x0f400000** |

- Both recovered with the reset. The fault check recovered as usual. -ETIMEDOUT, all five
  modules unloaded, the parent runtime-suspended.

**Facts (C):**
- **With the normal event program, a load through PA0 faults at 0x0f2d9000** (b1): PA0's
  leftover, like the r-registers' (attempt 31).
- **With the two-row event program, the task's code fetch faults at 0x0f400000** (b2). That's
  the USSE pixel heap's base, where code base 0 points under the >> 8 encoding. So that
  program's DOUTU started a task at code base 0, not the microkernel's entry, and the PA0
  load never ran.

**What it suggests (G):**
- **The DOUTU took a zero word 0.** One reading: 0x0a70 is the event program's data-segment
  length in dwords. At 6 it loads only part of the second row, and the word the DOUTU's
  `MOVS` reads is zero.
- **The PA0 question is still open.** The same probe with 0x0a70 = 8 would test it (0x0a70
  latches, attempt 36).

**Next:** rerunning with 0x0a70 = 8 is the coordinator's call, since it set this as the last
single-variable probe before the capture-board answer.
