# SGX530 stage 1, thirty-ninth attempt: no low register is writable either

**Board:** our OMAP3630 test board, openHC on the SD (7.3.3, the 02:16 build), up 1 h 22 min,
the owner-confirmed host key, the board lock held. No hang, no plug cycle.

**What ran:** powervr_sgx from sgx530 fd97aabe (the >> 8 code-base unit; modver-check 0
differ), `allow_unisolated=1` only, loaded four times.
- **The images:** the microkernel session's `cores/sgx530_aluwr_dst<d>.py` for d = 0-3 (its
  branch, cef97da2), built with `ukernel/build.py` and packaged by `drm/tools/mkukfw.py`.
  All eight hashes match the microkernel session's list.
- **What each does:** `or rD, rD, r17`, then `ld.a.d r3, rD, #0`. If the `or` wrote rD, the
  fault would be at rD's leftover | r17's leftover.

**Results:**

| rD | `BIF_FAULT` | rD's leftover (attempt 31) | The `or` result |
|---|---|---|---|
| r0 | 0x0055d000 | 0x0055d000 | 0x0fd7d000 |
| r1 | 0x0722a000 | 0x0722a000 | 0x0ff7b000 |
| r2 | 0x003e1000 | 0x003e1000 | 0x0ff7d000 |
| r3 | 0x08439000 | 0x08439000 | 0x0ff7d000 |

- Every fault was requestor b1, with the USE busy and `EVENT_TIMER` 0, INIT_STATUS 0.
- -ETIMEDOUT each time. All five modules unloaded and the parent runtime-suspended.

**Facts (C):**
- **An `or` into r0, r1, r2 or r3 doesn't change what a following load reads through that
  register,** as for r5 (attempts 34, 36 and 38).

**What it suggests (G):**
- **No low range of registers is writable from the task.** With attempts 31-38: the task
  executes and its loads read registers, but nothing the task writes to a register is seen
  afterwards.

**Next:** the PDS-to-attribute probe, which needs a driver variant (a DOUTA to PA0 before
the DOUTU) and the microkernel session's reader.
