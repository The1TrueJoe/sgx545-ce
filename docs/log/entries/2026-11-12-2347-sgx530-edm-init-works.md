# SGX530: the open microkernel reaches steady-state under the §9 real init (edm_init)

**Board:** our OMAP3630 test board, normal SD boot (7.3.3, ohc.boot=sd), freshly
rebooted to normal ~23:25 UTC, owner-reread pinned ED25519 host key (fingerprint
verified exactly before connecting), board lock held 23:43:44–~23:47 UTC. 78.5 °C,
load normal. One insmod cycle after a wrong-module retry (below).

**What ran:** powervr_sgx at b523faf3 (claude/sgx530-gap19-tests; omap3630 7.3.3 CI
green) with `allow_unisolated=1 edm_init=1`, and the open microkernel image
`sgx530_edm` (microkernel session f2dec59e, img 859a5133, pkg bd6b86ec, crc
0x3848d14e), deployed as `sgx530_ukernel.bin`. edm_init folds the §9 bare-DOUTU
launch into the real init, maps the data arena EDMPROTECT, host-writes
ui32InitStatus=1 after a settle, and does not wait on the microkernel's init status.

**Result: the microkernel starts and runs.**
- `event PDS base 0x0a68: wrote 0x014042c0, read 0x014042c0; data read 0x3 0x13d01`
  — the §9 event program installed.
- `after EDM init: ... timer 0x010118c7` — EVENT_TIMER advancing, no BIF fault
  (BIF int 0x0), EVENT_STATUS 0x0.
- `microkernel: init 0x1 version 0x00010000 ... heartbeat 135` and
  `[drm] microkernel started`, then `[drm] Initialized powervr_sgx 0.1.0 ... minor 1`.
- `insmod ... => 0` (not the -110 the probe tasks give). The module loaded and held.

So **§6 step 2 is proven on hardware**: the open microkernel reaches its steady-state
dispatch loop under the §9 real-init launch, with the host owning init status.

## Finding (C, needs reconciling): st.a.d to ctlblk-derived addresses COMMITS

`heartbeat` (control-block word 0x2a) read **135**, and `version` (word 0x18) read
**0x00010000**. The driver never writes these — `ta3dctl_fill()` sets only the
address fields (self/host_ctl/ccb_ctl/ccb/kernel_pd), and `pvrsgx_fwif.h` marks words
0x18+ as "the microkernel's own state, zero at every start" (fresh alloc is `__GFP_ZERO`).
heartbeat=135 after ~137 ms at the 1 kHz timer = one increment per tick, each a
`ld; add; st.a.d` to ctlblk+0xa8. **So the microkernel's `st.a.d` to ctlblk(r17)-derived
addresses committed** — 135× for heartbeat, once for version.

This **appears to contradict** log 2026-11-12-2201 (stor5: "st.a.d drops"). The likely
difference is the store base — stor5's vs the microkernel's loader-patched r17=ctlblk.
If ctlblk-derived `st.a.d` commits, the EDM design may simplify a lot: do_3d's
WAIT_3D/WAIT_FREE arming would commit (rendezvous works → the pixel_done/free_done
reduction may be unnecessary), and kick_adv's CCB read-offset advance would commit (the
microkernel could own the read offset). Flagged to the microkernel session to pin down
which `st.a.d` drops (temp-based?) vs commits (ctlblk/sa-based) before more reductions.
The completion reduction is on hold pending that.

## Bug: the EDM module unload hangs

On `rmmod powervr_sgx`, rmmod returned 139 and the module stuck in GOING state
(refcount -1), holding the four helper modules (5 loaded, none unloadable). The board
stayed responsive; no kernel oops in dmesg. The teardown path still runs the DDK
microkernel's power-down handshake, which the §9/stateless path does not complete, so
the unload blocks. **To fix:** an edm_init teardown that does not wait on the microkernel
(the host owns shutdown). The board needs a reboot to clear the stuck module; ta3d-state's
following SD cold boot does that.

**Operational note:** the first insmod used the wrong module (b1689a57, pre-edm_init) —
`unknown parameter 'edm_init' ignored` → the normal-init path timed out (-110). Caught it,
redeployed the b523faf3 build (which carries edm_init), and got the result above. The
cold-boot GPU reference for ta3d-state was also captured (50000000.gpu exists under the
5000fe00.target-module; the module is runtime-PM suspended when idle).

**Next:** (1) reconcile the store-commit finding with stor5 (microkernel session) — it may
reshape the EDM plan; (2) fix the edm_init teardown; (3) the single-render kick test once
the store question settles and a board slot frees.
