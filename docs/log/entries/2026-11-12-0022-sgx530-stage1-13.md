# SGX530 stage 1, thirteenth attempt: void (0x0a6c = 4 started the PDS outside our program)

**Correction (2026-11-12).** This attempt's baseline came from a misreading of the twelfth:
0x0a6c counts 16-byte rows, not dwords. So 0x0a6c = 4 started the PDS at byte 0x40, past our
0x18-byte event program, in PDS1's slot. 0x5012b8 is that row, not our MOVS. **The
attempt's results say nothing about our program.** The "facts" and "suggests" sections below
are kept as first written and don't hold. The normal start is back to 0x0a6c = 1.

**Board:** our OMAP3630 test board, our kernel on the SD (7.3.3, the 02:16 build). 75 °C
before and after.

**What ran:** powervr_sgx from sgx530 f251cf31 (CI: omap3630 43160077828, powervr-sgx
43160071729 and upstream 43160074884, all green), `allow_unisolated=1 code_base_pads=1
stage1_sweep=1`, with the landing-pad image `sgx530_bases` (f7de7b95…).
- **The new baseline:** 0x0a6c = 4 in the SGX530's normal start (the event program's code
  offset in dwords, twelfth attempt), with the kicker fix, the pads and the TI layout.
- **The sweep, each variant one change from that baseline:**
  - MOVS cc 0 first;
  - 0x0a70 ∈ {0, 1, 2, 3, 4, 8, 16};
  - MOVS dest 4/6/7/1/0/2, cc 3;
  - DOUTU word 1 = 0, the 2-dword interleave, all-slots, 4 or 0 temporaries, DM 2,
    W0+DM2, all-slots+T4;
  - the MOVS-side variants again with 0x0a70 = 4.

  That's 34 variants, then the fault check.

**Results:**
- **No variant ran the ladder or reached a pad.** `EVENT_TIMER` stayed 0 in all 34. No
  variant depended on the one before it.
- **`PDS_PC_BASE` showed only 0x5012b8 (the MOVS), 0xf75c (not ours) and 0 in every
  variant, cc 0 included.** It never showed 0x5012bc, the HALT after the MOVS.
- **The fault check:** `BIF_INT_STAT` 0x4004, `BIF_FAULT` 0x0e800000, then "recovered, BIF
  int 0x0".
- -ETIMEDOUT, all five modules unloaded, the parent runtime-suspended.

**Facts (C):**
- **With 0x0a6c = 4, the PDS's PC reaches the event program's MOVS and goes no further, even
  when the MOVS's condition is 0.** A MOVS that ran with cc 0 would move the PC to the HALT.
- **No 0x0a70 value in {0, 1, 2, 3, 4, 6, 8, 16} changes that,** nor any MOVS destination,
  DOUTU, interleave, temporaries or data-master change tried.

**What it suggests (G):**
- **The PDS fetches the MOVS's address but doesn't execute it.** It either fails to decode
  it as a valid instruction on the SGX530, or waits on something before executing any
  instruction.
- **The SGX530's PDS instruction encoding may differ from the SGX545's** (PDS.md describes
  the 545's). A bare HALT as the first instruction would test whether the PDS executes
  anything at all.
- **The 0xf75c activity is unchanged by everything we vary.** U.
