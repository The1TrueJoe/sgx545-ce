# SGX530 stage 1, twenty-fifth attempt: the minimal USSE probe stores nothing

**Board:** our OMAP3630 test board, our kernel on the SD (7.3.3, the 02:16 build), up 22 min,
the owner-confirmed host key, the board lock held. 77 °C before, 75 °C after. No hang, no
plug cycle.

**What ran:** powervr_sgx from sgx530 fd97aabe (the >> 8 code-base unit; CI as in the
twenty-fourth attempt, modver-check 0 differ), `allow_unisolated=1` only: no sweep, no pads.
- **The image:** the microkernel session's probe, `cores/sgx530_usse.py` (its branch,
  d47b7bcd), built with `ukernel/build.py`: 104 bytes, sha256 cb18a5a7…, crc 0xac4ecbbd.
  Packaged by `drm/tools/mkukfw.py` (sha256 0bcce2c7…): entry program 0 at 0x0, one patch
  (0x0 ← the TA/3D control block).
- **The event task:**
  1. `st.a.d`: control block 0x28 = 0xbeef1;
  2. `str`: `EVENT_TIMER` = 0xa5a;
  3. `st.a.d`: control block 0x18 = 0xc0de2;
  4. a branch to itself.

**Results:**
- The event program sat at 0x01400070 above `PDS_EXEC_BASE` (read back).
- From 100 ms to 500 ms after the kick: `BIF_INT_STAT` 0x4004, the clock status busy
  (0x00110000), `EVENT_TIMER` 0.
- **Control block 0x28 = 0, 0x18 = 0** ("version 0, wait 0" in the status words), INIT_STATUS
  0.
- **`BIF_FAULT` 0x09039000**, requestor b2.
- -ETIMEDOUT. The failed-start path held the cores in reset, then all five modules unloaded
  and the parent runtime-suspended.

**Facts (C):**
- **None of the probe's three stores landed,** not even the first `st.a.d`.
- **The task faults at 0x09039000 with requestor b2.** With the bases image (the
  twenty-fourth attempt) the same code base 15 faulted at 0x08039000. The low 0x39000 is
  the same, and the two differ by 0x01000000.

**What it suggests (G):**
- **The task fails at or before its first instruction:** a store that ran would have
  written 0xbeef1.
- **The fault address depends on the image** (0x08039000 → 0x09039000 between two images
  with the same code base, DOUTU word and event address bits). So it may come from the
  instruction words the task fetches, or from the patched value, rather than from the
  driver's setup. The microkernel session can map it against both images' first words.
