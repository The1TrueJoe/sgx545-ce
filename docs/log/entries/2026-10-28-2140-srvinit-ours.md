# srvinit loads openHC's microkernel

`srvinit` gained a `-o ukernel.bin` mode that loads openHC's own microkernel
(`ukernel/`) in place of the DDK's, the last software piece before the GPU can
be brought up on ours.

## The change (srvinit/srvinit.c)

Three differences from the `-f` path, nothing else touched:

- the image loads at its own size (`load_ours`, a multiple of 8), and the
  ukernel and event-program buffers are sized for it (`bufsz`);
- no `limm` patching — ours has no placeholders, it reads every address from
  the control block;
- the event program (`pds_ours`) DMAs the TA3D control block into the
  secondary attributes and starts our entry at offset 0 in one program, and
  the host-kick table is the identity (ServiceAddress = command type).

## Validated offline

Built native (arm64, clang) for the plan mode. `srvinit -o ukernel.bin -n`
produces an event program of DOUTD (control `0x3c0003f`) + DOUTU (code base
15, offset 0) + HALT, and copies our image byte-identically. The `-f` path is
unchanged: it still patches the nine `limm` sites (the one-byte-span
difference in its written `ukernel.bin` is exactly the 0xd60 patch) and builds
the plain DOUTU event program. `srvinit` also still cross-builds for
x86_64-linux-musl with zig.

## Next

This is the bring-up path: the event kick runs the program, our init entry
sets `ui32InitStatus`, the host's poll succeeds. A full frame also needs our
microkernel's unified event dispatch (one entry that reads `EVENT_STATUS` and
vectors to the TA / 3D / completion handlers) — the run_ours.py harness drives
those entries separately today. After that, the EA3: bring-up first, then a
replayed frame, es2gears, recovery. No hardware has been touched.
