# The PDS as a Mesa isaspec description; the winsys and the driver build their PDS programs through it

`mesa/src/sgx545/pds/sgx545_pds.xml` describes the PDS programs of
`docs/PDS.md` in Mesa's isaspec format: the instructions (MOVS/DOUT, ADD,
MUL16, OR, AND, XOR, op d s1, TST, BRA, SHL, SHR, HALT) and the DOUT data
words (DOUTU 0/1, DOUTD control, DOUTI 0/1, DOUTA control). isaspec generates
the encoder and the disassembler; a small assembler reads the disassembler's
text back. The text is PDS.md's "Text notation" (proposed here, adopted in
PDS.md 31aa06e, which `tools/pds/dis.py` also prints).

The winsys and the driver no longer hand-assemble PDS words:

- `sgx545_frame.c` builds every program through the encoder: pixel,
  secondary/state, DMA, vertex fetch, pixel event, background, TA terminate.
  The `MOVS`/`ALU`/`TST`/... bit macros, `doutu_w0`'s and `dma_ctrl`'s shifts
  and the DOUTI/DOUTU/DOUTA constants are gone.
- A fragment program's iterations cross the driver/winsys interface as
  `struct sgx545_pds_douti` (`struct sgxws_prog`). The driver's DOUTI builder,
  its PA count and `varyings_match` read fields, not bits; the winsys
  encodes them.

## What isaspec couldn't express

- **Data words aren't instructions.** isaspec decodes from `#instruction`
  only, so the DOUT words are encode-only roots: the disassembler shows the
  data segment in hex. Their unused decode tables need
  `-Wno-unused-variable`.
- **Generated names.** isaspec names its functions after the output file's
  name up to the first `-`, so the files are `sgx545pds-isa.*`
  (`sgx545-pds` would give a second `sgx545_isa_disasm`).
- **MOVS's operands** are two pair rows and four 2-bit selects; the text
  shows the four words sent (derived fields), and a row no select reads as
  `[r1=n]` / `[r2=n]` so the text stays lossless.

## Gaps in PDS.md

Asked of the spec side and answered in PDS.md 31aa06e:

1. The text notation: a new "Text notation" section, as proposed here.
2. Bits no field names ("Bits no field names"): 0 in all 25 captures, an
   encoder writes 0 and a decoder may refuse them. TST bit 27, bits 0-7 and
   the source `sel` doesn't pick; BRA bit 27; ALU bits 7-8; DOUTU w0 22-23;
   DOUTU w1 all but 1, 2, 22-25; DOUTI 5-8, 17-20, 31; DOUTI w1 7-31; DOUTD
   26-31; DOUTA 0-7 and 16-31.
3. DOUTI bits 25-26: a 2-bit field, 3 from GL's builder and 0 on the clear's
   colour and the background sample.
4. Widths: ALU dst 7 bits, shift dst 8 bits, DOUTU w0 24-31 one field, the
   DOUTA register bits 8-15.
5. Names: `op0xd.s1`, `op0x4.s1`, `op0x6.s1`; opcode a with s = 0 never seen;
   `dout<n>` for other DOUT targets.
6. The half bit in 32-bit ops: unknown, never emitted, printed `.hi`.
