# SGX530 stage 1, thirty-seventh attempt: the rest of the SGX545's part 2 changes nothing

**Board:** our OMAP3630 test board, our kernel on the SD (7.3.3, the 02:16 build), up 1 h 9 min,
the owner-confirmed host key, the board lock held for both loads. 77 °C before. No hang, no
plug cycle.

**What ran:** powervr_sgx from sgx530 b487d86a (CI: omap3630 43194631590, powervr-sgx
43194624085 and upstream 43194628029, all green; modver-check 0 differ), `allow_unisolated=1
stage1_sweep=1 stage1_vendor=1`, loaded twice: with `aluwr` (packaged 18ce50ba…), then with
the real SGX530 image (packaged 34aa17c4…).

**Approval:** the coordinator approved, under the standing go, exactly these SGX530
offsets at the SGX545 capture's values: 0x818, 0x810, 0x814, 0x800, 0x804, 0x4e8 and 0x13c
(new), plus 0xa00, 0xa78, 0xaac, 0xabc, 0xa7c and 0xa80 (approved in attempt 18). Each is
read before the write, logged, and put back after its variant.

**The question:** no register write has landed in attempts 31-36. The SGX530's part 2 writes
three registers where the SGX545's writes sixteen. Do the missing ones set up the USE's
register file?

| # | Writes |
|---|---|
| 0 | none (baseline) |
| 1 | 0x8xx and 0xaxx: 0x818, 0x810, 0x814, 0xa7c, 0xa80, 0xa78, 0xaac, 0xabc, 0x800, 0x804, 0xa00 |
| 2 | variant 1, plus 0x13c and 0x4e8 |
| 3 | 0x818, 0x810, 0x814 |
| 4 | 0x800, 0x804 |
| 5 | 0xa7c, 0xa80, 0xa78, 0xaac, 0xabc, 0xa00 |

**Results:**
- **`aluwr`:** every variant faulted b1 at 0x0c004000, r5's leftover.
- **The real image:** every variant faulted b1 at 0x0fd79000.
- Every fault recovered with the reset. No variant ran the ladder or set INIT_STATUS.
- -ETIMEDOUT for both loads. All five modules unloaded and the parent runtime-suspended.
- **The read-backs:** every register read 0 before its write.
  - They latch: 0x804 = 0xffff, 0xa00 = 0x7c000, 0xa78 = 0x2c, 0xabc = 0xe.
  - They read 0 after a nonzero write: 0x800 (0x30), 0x810 (1), 0x814 (0xffff), 0x818
    (0x7ff), 0x4e8 (0x100), 0xaac (0x45).
  - Written as 0, so latching isn't shown: 0x13c, 0xa7c, 0xa80.

**Facts (C):**
- **None of the thirteen SGX545 part-2 writes, together or in these subsets, makes a
  register write land,** in `aluwr` or the real image.
- **0x800, 0x810, 0x814, 0x818 and 0x4e8 don't hold a value on the SGX530.** They're
  recorded in the fact sheet ("The PDS block setup").

**What it suggests (G):**
- **The missing part-2 writes aren't why writes don't land.** Several of them may not exist
  on the SGX530.
