# SGX530 gate 1, ldr5_ctl: inconclusive — the OR's operand is a subset of r5's leftover

**Board:** our OMAP3630 test board, up 12 h 59 min (the same boot as attempts 40-47, T1, T2
and §9), the owner-reread pinned ED25519 host key, the board lock held 21:43:05-21:43:53 UTC.
77 °C. No hang, no plug cycle.

**What ran:** powervr_sgx from claude/sgx530-gap19-tests (omap3630 CI 43309942028, green), one
load, `allow_unisolated=1 stage1_vlaunch=1`. Image `sgx530_ldr5_ctl` (matching the microkernel
session's hashes, img ed9b1e80…, pkg 82a70edc…): `aluwr` with the `or` replaced by a `nop`, so
the `ld` reads r5's **raw** leftover under §9 — the model-free control for whether the `or`
retired the temporary.

| Image | op on r5 | `BIF_FAULT` |
|---|---|---|
| `sgx530_ldr5_ctl` | `nop` (raw r5) | 0x0fa93000 |
| `sgx530_aluwr` (§9, log 2026-11-12-2115) | `or r5, r5, r17` | 0x0fa93000 |
| `sgx530_aluwr_o0` (§9, log 2026-11-12-2131) | `or o0, r5, r17` | 0x0f373000 |

r17 is patched to the control block (ctlblk) address = **0x0f003000** (kernel_data.base
0x0f000000 + TA3DCTL offset 0x3000).

**Facts (C):**
- **`ldr5_ctl` = `aluwr` = 0x0fa93000.** The `or` version and the `nop` version fault at the
  same address.
- **ctlblk (r17) = 0x0f003000.**

**Why this does not settle gate 1 (G):**
- **r17's value is a subset of r5's leftover:** 0x0f003000 & 0x0fa93000 = 0x0f003000. So
  `r5 | r17 = 0x0fa93000` — the OR changes no bit of r5. `aluwr` == `ldr5_ctl` is therefore
  consistent with the temporary retiring (the OR ran but was a no-op) **and** with it not
  retiring (r5 untouched). The control can't distinguish them here.
- **The three values don't close arithmetically.** With r5 = 0x0fa93000 and r17 = 0x0f003000,
  `aluwr_o0` = `r5 | r17` should be 0x0fa93000, but it is 0x0f373000. So the per-image register
  seed under §9 is not a single consistent (r5, r17) — the microkernel session's register-map
  decode is needed.
- **A clean decider needs an OR operand disjoint from 0x0fa93000**, so a retired write shows a
  bit the leftover lacks. The microkernel session builds that probe.

**What stands (C, from §9):** gate 2 is closed — the task launches and runs under the vendor
launch, repeatably. Gate 1 (temporary/pa retire) is **undecided**; only the output's retire is
proven (stage 1). §9's value is the launch, whichever way gate 1 falls.

**Next:** the microkernel session's disjoint-operand probe to settle gate 1, and its decode of
the three fault addresses.
