**Runs 20-23, uniform blocks** (`SGX_DEBUG=ubo`, the first CE5300 board):
- Run 20 (fee7953e): `sgx_ubo` drew nothing, with job page faults at 0. st
  numbers a program's first block 0 in `load_ubo` and binds it as constant
  buffer 1; the driver filled only `SGX_K_UBO + 1..12`, so block 0's
  address stayed 0. Without the native integers the block offsets also
  arrive as floats (1280 as 0x44a00000). Each fault reset the GPU, and the
  run went on.
- Run 21 (fba2d708: block n is buffer 1 + n, blocks only with `glsl130`):
  - `sgx_ubo` exact in all four quads; no page fault or timeout;
  - piglit's 316 `arb_uniform_buffer_object` tests: 33 pass, 282 skip,
    1 fail (`minmax`, the 1024 fragment uniform components). Under GL 3.1 /
    GLSL 1.40: 41 pass, 275 fail.
  - 270 of the fails check in the vertex program and pass the result on as
    a `flat out int`.
- Run 22: 12 of those, their checks moved to the fragment program: 10 pass,
  2 not run (ssh logins refused). A flat int varying alone, with no block,
  fails, and so does the first flat varying of a program. The second flat
  varying, a uint, comes back exact, as does a smooth float. The driver
  doesn't do flat varyings yet (docs/GL3.md, "Flat varyings"); why a flat
  int of 1 comes back wrong where a flat uint comes back right is not known.
- Run 23 (fba2d708, the default path): dEQP 78 F / 16637 P; zs, ms, ff and
  dEQP no difference against run 19, gl21 only fixed-clip-enables (Fail where
  run 19 had Flake). The two fragment-checked tests run 22 missed pass: 12
  of 12. Every run used the 92442046 ea3-v2 kernel and the fw-ee166e5c
  microkernel image.
- Run 24 (stage21, fba2d708, the same kernel and microkernel): flat varyings,
  each written in the vertex program and its four bytes written out as the
  colour. A flat float 1.5, int 1, int 0x01020304 and uint 0x8080c0c0 arrive
  exact.
  - Int -1 arrives 0x7fffffff. Its vertex program writes it as an immediate,
    with no constant.
  - Two flat ints in one program, uint 7 then int 1, both arrive wrong; one
    alone is exact.
  - Both point at the compiler's integer-varying halves; handed to the
    compiler side with the logs.
