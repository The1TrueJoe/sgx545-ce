# SGX530 gap 19, test T1: READONLY refuses the microkernel task's store

**Board:** our OMAP3630 test board, up 10 h 30 min (the same boot as attempts 40-47), the
pinned host key, `hc250.lock` held 19:15:11-19:16:21 UTC. 75-77 °C. No hang, no plug cycle.

**What ran:** powervr_sgx from claude/sgx530-gap19-tests 8747626a (CI: omap3630
43282516644, green). modver-check: 0 differ against the board's own module tree. Four
loads, each with `allow_unisolated=1`. The images are attempt 47's, and every SHA-256
matches the microkernel session's list.

1. **`sgx530_pa0`** with `stage1_sweep=1`. Its one-row DOUTA variant sets PA0 to the
   control block's version-word address (TA3DCTL + 0x60, in the kernel data arena), as in
   attempt 47.
2. **`sgx530_pa0`** with `stage1_data_ro=1`: the kernel data arena mapped
   `READONLY | CACHECONSISTENT`. The task loads through PA0.
3. **`sgx530_stout_o0`** with `stage1_data_ro=1`: the task stores o0 through PA0.
4. **`sgx530_stout_o0`** with the arena writable (the default, no `EDMPROTECT`): the
   control.

**Results:**

| Load | Data arena | Access through PA0 | `BIF_INT_STAT` | `BIF_FAULT` |
|---|---|---|---|---|
| `pa0` sweep | writable | load (baselines) | 0 | none |
| `pa0` | READONLY | load | 0 | none |
| `stout_o0` | READONLY | store | **0x4** | **0x0f003000** |
| `stout_o0` | writable | store | 0 | none |

- The sweep's two DOUTA variants faulted at code base 0 (0x4004, 0x0f400000), as in
  attempts 46 and 47.
- In every load the USE stayed busy (0x00110000) through 500 ms. The fault in load 3
  stayed set throughout.
- The store scans found the value in neither arena, as in attempt 47.
- -ETIMEDOUT for each load. All five modules unloaded and the parent runtime-suspended.

**Facts (C):**
- **READONLY refuses the USSE task's store on the SGX530.** The fault address is the
  store's page.
- **READONLY lets the task's load through.**
- **The READONLY store fault reads 0x4 in `BIF_INT_STAT`.** The `EDMPROTECT` store fault
  of attempt 45, at the same page, read 0x4004.

**What it suggests (G):**
- **b14 of `BIF_INT_STAT` isn't simply read-or-write.** It's set for the `EDMPROTECT`
  store fault, for loads from unmapped pages (0x4002) and for code-base-0 fetches (0x4004),
  and clear for the READONLY store fault. It may tell a protection fault from a missing
  page, or `EDMPROTECT` from READONLY. That isn't settled.
- **For gap 19:** the READONLY layer works against USSE stores on this core.
  Everything the microkernel only reads (its image, the PD table, init data) can be
  READONLY in every client's directory. PBE, ISP and TA writes against READONLY still need
  a running microkernel.
