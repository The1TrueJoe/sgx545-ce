# SGX530 stage 1, thirty-fifth attempt: no DOUTU temporaries encoding makes register writes land

**Board:** our OMAP3630 test board, openHC on the SD (7.3.3, the 02:16 build), up 55 min,
the owner-confirmed host key, the board lock held for both loads. 77 °C before. No hang, no
plug cycle.

**What ran:** powervr_sgx from 16baa779, built on wip/sgx530-a35b (CI: omap3630
43188557237, powervr-sgx 43188549687 and upstream 43188553410, all green; modver-check 0
differ). It's a951de81 plus the temporaries-field variant. `allow_unisolated=1
stage1_sweep=1`, loaded twice: first with the microkernel session's `aluwr` image
(packaged 18ce50ba…, as in the thirty-fourth attempt), then with the real SGX530 image
(packaged 34aa17c4…, as in the twenty-sixth).

**The question:** attempts 31-34 fit a task with no temporaries, where every register
write is dropped. Does the SGX530 read the temporaries count from somewhere else in DOUTU
word 0?
- **The baseline:** the driver's word 0, which has the temporaries field (b24-31) = 6 for
  the SGX530's 24 temporaries. That clears b27.
- **Temporaries field 8:** 32 temporaries, which sets b27 as the SGX545's own entries do.
- **The free groups:** the bits that don't move the code fetch (attempts 21-22), set on top
  of the normal word: b8-15 (0xff00), b19-23 (0xf80000), b28-31 (0xf0000000).
- After each variant, a fault gets the recovery reset.

**Results:**

| Variant | `aluwr` | Real image |
|---|---|---|
| baseline (field 6) | b1 fault at 0x0c004000 | b1 fault at 0x0fd79000 |
| temporaries field 8 | b1 fault at 0x0c004000 | b1 fault at 0x0fd79000 |
| \|= 0xff00 (b8-15) | b1 fault at 0x0c004000 | **no fault**: BIF int 0, USE busy (0x00110000), `EVENT_TIMER` 0 |
| \|= 0xf80000 (b19-23) | b1 fault at 0x0c004000 | b1 fault at 0x0fd79000 |
| \|= 0xf0000000 (b28-31) | b1 fault at 0x0c004000 | b1 fault at 0x0fd79000 |

- Every fault recovered with the reset. No variant ran the ladder or set INIT_STATUS. The
  fault check recovered as usual.
- -ETIMEDOUT for both loads. All five modules unloaded and the parent runtime-suspended.

**Facts (C):**
- **No DOUTU word 0 tried makes `aluwr`'s `or` write r5:** not the temporaries field at 8,
  and not any free group set to all ones.
- **The real image behaves the same, except with b8-15 set,** where it ran 100 ms without a
  fault and without initialising.

**What it suggests (G):**
- **The dropped writes don't come from the DOUTU temporaries count,** in the SGX545's field
  or any free bit tried.
- **The real image's b8-15 cell may be the entry moving inside page 0:** b8-15 as offset
  bits below the 4 KiB the fault page shows, per the microkernel session's reading of
  attempt 21. That would start it somewhere else in the image, where it runs without a
  fault.

**Next:** for the microkernel session: `phas.i`'s temporaries field, and telling "b8-15
move the entry" apart from "b8-15 matter otherwise".
