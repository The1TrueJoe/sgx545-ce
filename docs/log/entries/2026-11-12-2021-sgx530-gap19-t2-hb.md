# SGX530 gap 19/7, test T2 and H-B: the list-0 switch is clean; the store isn't held in the BIF

**Board:** our OMAP3630 test board, up 11 h 37 min (the same boot as attempts 40-47 and T1),
the pinned host key, the board lock held 20:21:26-20:22:35 UTC. 75-77 °C. No hang, no plug
cycle.

**What ran:** powervr_sgx from claude/sgx530-gap19-tests bcdebe45 (CI: omap3630 43298300240,
green). modver-check: 0 differ against the board's own module tree. Four loads, each with
`allow_unisolated=1`. The images' SHA-256 match the microkernel session's list, the
`ldloop` package among them (img 1c907668…, pkg 7836ee76…).

1. **`sgx530_pa0`** with `stage1_sweep=1` (the baseline; never starts).
2. **`sgx530_ldloop_pa0`** (`phas.i; L: ld.a.d r3, pa0, #0; wdf; ba L`) with
   `stage1_dirswap=1`: after the failed start, with the task looping on a load from PA0 (the
   control block in the kernel data arena), move list 0 between directories and read the BIF
   after each step.
3. **`sgx530_stout_o0`** with `stage1_scan=0x0fd7d000 stage1_flush=1`: the store task, then a
   host BIF flush and directory-cache invalidate before the DRAM scan.
4. **`sgx530_stout_r5`** with `stage1_scan=0x0c004000 stage1_flush=1`: the same, r5's value.

**T2 results (gap 7, `stage1_dirswap`):** firmware PD 0x8dec9000, A' (maps the kernel code
and data heaps) 0x8de4e000, B (maps only the code) 0x8de91000.

| Step | list 0 | `BIF_INT_STAT` | `BIF_FAULT` |
|---|---|---|---|
| before | firmware | 0 | none |
| A' with INVALDC | A' | 0 | none |
| B without INVALDC | B | 0 | none |
| B with INVALDC | B | **0x4002** | **0x0f003000** |
| back on firmware's | firmware | 0x4002 | 0x0f003000 (the task re-faults) |

**H-B results (the host flush):** both store loads, the flush showed `EVENT_STATUS`
0x00000000 → 0x00000000 and `BIF_MEM_REQ_STAT` 0x0 → 0x0, and the scans found the value in
neither arena (0 hits).

- -ETIMEDOUT for each load. All five modules unloaded and the parent runtime-suspended each
  time.

**Facts (C):**
- **The list-0 switch with the BIF directory-cache invalidate leaves no stale translation.**
  The looping task's load from PA0's page (mapped in A', not in B) faults exactly once list
  0 is on B *and* the directory cache is invalidated. B without the invalidate didn't fault:
  the BIF still held A''s translation.
- **The invalidate is necessary**, not only sufficient: the stale translation of a removed
  directory survives the `BIF_DIR_LIST_BASE0` write alone.
- **A host BIF FLUSH plus INVALDC doesn't make the task's store appear**, and the BIF
  reports no outstanding reads (`BIF_MEM_REQ_STAT` 0). The store is not held in the BIF.

**What it suggests (G):**
- **For gap 19:** the directory-switch half of a boundary is sound on this core (gap 7
  confirmed). Switching list 0 per kick still can't isolate concurrent client and microkernel
  work on one list (the design's reason for picking the instruction checker plus READONLY,
  not the switch), but the switch itself is clean when a VM's directory is torn down.
- **The write-retire/store blocker isn't a flush gate** (H-B negative) and isn't EDMPROTECT
  (H-A, from the PTE: the store page had bit 4 clear). It stands as the microkernel session
  concludes: the task has no write context. The vendor-launch test (vendor-setup §9) is the
  remaining lead, held on a clean-room provenance decision.
