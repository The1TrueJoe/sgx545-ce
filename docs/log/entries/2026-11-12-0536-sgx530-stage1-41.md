# SGX530 stage 1, forty-first attempt: an output register takes the task's write

**Board:** our OMAP3630 test board, our kernel on the SD (7.3.3, the 02:16 build), up 1 h 51 min
(the fortieth attempt's boot), the owner-confirmed host key, the board lock held for both
loads. 77 °C before. No hang, no plug cycle.

**What ran:** powervr_sgx from sgx530 f85c22d9 (CI: omap3630 43200799580, powervr-sgx
43200791370 and upstream 43200795536, all green; modver-check 0 differ). Two loads, as the
coordinator approved:
1. **The PA0 confirmation:** the microkernel session's `sgx530_pa0` (packaged f59ce697…)
   with `stage1_sweep=1`. The variants:
   - the normal event program;
   - the normal program with DOUTU word 1 = 0;
   - a one-row program `[0x0e860000, 0, 0, doutu]`, which does a DOUTA (0x0e860000, 0) to
     PA0, then a DOUTU (doutu, 0, 0). Words 0 and 3 sit in the same place under either data
     interleave.
2. **The output-register write:** the microkernel session's `sgx530_aluwr_o0` (its branch,
   ab1f53cc; image 3d8e8a72…, crc 0x8050de8b, packaged c30c27a1…, both matching), without
   the sweep. It runs `or o0, r5, r17`, then `ld.a.d r3, o0, #0`.

**Results:**

| Load | Variant | `BIF_INT_STAT` | `BIF_FAULT` |
|---|---|---|---|
| `sgx530_pa0` | normal event program | 0x4002 (b1) | 0x0e850000 |
| `sgx530_pa0` | DOUTU word 1 = 0 | 0x4002 (b1) | 0x0e850000 |
| `sgx530_pa0` | one-row DOUTA to PA0 | 0x4004 (b2) | 0x0f400000 |
| `sgx530_aluwr_o0` | normal event program | 0x4002 (b1) | **0x0fd7d000** |

- All recovered with the reset. -ETIMEDOUT for both loads. All five modules unloaded and
  the parent runtime-suspended.

**Facts (C):**
- **An `or` into o0 lands, and a load through o0 reads it:** 0x0fd7d000 = r5's leftover
  (0x0c004000) | r17's leftover (0x0fd79000). That's the first register write by the task
  seen on the SGX530.
- **PA0 still holds 0x0e850000,** from the fortieth attempt's DOUTA nineteen minutes and
  several loads earlier.
- **The task starts and runs the image normally with DOUTU word 1 = 0.**
- **The one-row DOUTA program, like the two-row one, starts its task at code base 0.** With
  a DOUTA before it, the DOUTU's word 0 comes out as 0 in both layouts, while the same
  DOUTU words without the DOUTA work.

**What it suggests (G):**
- **The task can write output registers where it can't write temporaries.** Pointers in
  PDS-set attributes and scratch in outputs is a feasible SGX530 microkernel structure.
- **A DOUTA ahead of the DOUTU, in our MOVS form, leaves the DOUTU without its word 0.**
  How the SGX530 sequences the two DOUTs is the open part.
**Follow-up, 10:38 UTC, same boot (approved by the coordinator):** one plain `sgx530_pa0`
load with the normal event program and no sweep faulted b1 at **0x0e860000**.
- **So the one-row DOUTA wrote PA0 = 0x0e860000 (C),** though its DOUTU then started the task
  at code base 0.
- **In both layouts the DOUTA lands and the DOUTU after it doesn't.**

**Next:** making a DOUTA and a DOUTU work in one event program, which the microkernel
session's restructure needs.
