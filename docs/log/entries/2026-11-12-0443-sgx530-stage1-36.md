# SGX530 stage 1, thirty-sixth attempt: phas.i's temporaries field doesn't make writes land either

**Board:** our OMAP3630 test board, openHC on the SD (7.3.3, the 02:16 build), up 58 min,
the owner-confirmed host key, the board lock held. No hang, no plug cycle.

**What ran:** powervr_sgx from sgx530 fd97aabe (the >> 8 code-base unit; modver-check 0
differ), `allow_unisolated=1` only, loaded three times.
- **The images:** the microkernel session's `cores/sgx530_aluwr_ph<t>.py` for t = 8, 6 and
  63 (its branch, 0e768a60), built with `ukernel/build.py` and packaged by
  `drm/tools/mkukfw.py`. All six hashes match the microkernel session's list.
- **What each does:** the thirty-fourth attempt's `aluwr` (`or r5, r5, r17`;
  `ld.a.d r3, r5, #0`), with `phas.i #0, #t` first. That's 32, 24 or 252 temporaries in
  `phas.i`'s temporaries field, which the real entry leaves at 0.

**Results:** the same in all three runs. `BIF_INT_STAT` 0x4002 (requestor b1), `BIF_FAULT`
**0x0c004000** (r5's leftover), the USE busy (0x00110000), `EVENT_TIMER` 0, INIT_STATUS 0.
-ETIMEDOUT each time. All five modules unloaded and the parent runtime-suspended.

**Facts (C):**
- **With `phas.i`'s temporaries field at 8, 6 or 63, the `or` still doesn't write r5.**
- **No register write of any kind has landed in attempts 31-36:** not `limm`, not the ALU,
  and not `str` to `EVENT_TIMER`. Every read gives the register's stable leftover.

**What it suggests (G):**
- **The temporaries count, from the DOUTU (thirty-fifth attempt) or from `phas.i` (this
  one), isn't what drops the writes.**
- **What's left:** the SGX545 instruction encodings' destination fields on the SGX530; a
  setup the SGX530 needs before writes commit; or writes landing where later reads don't
  look.

**Next:** for the microkernel session.
