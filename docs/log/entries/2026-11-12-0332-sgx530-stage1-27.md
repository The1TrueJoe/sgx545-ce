# SGX530 stage 1, twenty-seventh attempt: the first data load is the fault

**Board:** our OMAP3630 test board, our kernel on the SD (7.3.3, the 02:16 build), up 32 min,
the owner-confirmed host key, the board lock held. 77 °C before, 75 °C after. No hang, no
plug cycle.

**What ran:** powervr_sgx from sgx530 fd97aabe (the >> 8 code-base unit; modver-check 0
differ), `allow_unisolated=1` only.
- **The image:** the microkernel session's mirror probe, `cores/sgx530_usse_mirror.py` (its
  branch, 7d7cc5de): 96 bytes, sha256 8d385fcd…, crc 0xe92af0c4. Packaged 9566c0a8…, both
  matching the microkernel session's. Patches: 0x8 ← the TA/3D control block, 0x10 ← the PD
  table.
- **What it does:** it copies the real image's entry preamble exactly:
  - `phas.i`, then both patched limms (r17 = the control block, r14 = the PD table);
  - the real entry's first load, the heartbeat `ld.a.d r3, r17, #42`;
  - then stores what it read to control block 0x28, writes `EVENT_TIMER` = 0xa5a, and
    branches to itself.
- **The patched values,** from the driver's fixed layout (D, not logged by the driver): the
  control block at kernel data + 0x3000 = 0x0f003000, the PD table at kernel code + 0xf000
  = 0x0ec0f000.

**Results:**
- The event program sat at 0x01400060 above `PDS_EXEC_BASE` (read back).
- From 100 ms to 500 ms after the kick: `BIF_INT_STAT` **0x4002** (requestor b1),
  `BIF_FAULT` **0x0fd79000**, the clocks busy, `EVENT_TIMER` 0.
- Control block 0x28 = 0, INIT_STATUS 0.
- -ETIMEDOUT. The failed-start path held the cores in reset, then all five modules unloaded
  and the parent runtime-suspended.

**Facts (C):**
- **The mirror probe reproduces the real image's fault exactly:** b1 at 0x0fd79000, as in
  the twenty-sixth attempt's real image and the twenty-fourth attempt's 0xec001 variant.
- **No store after the load landed** (control block 0x28 and `EVENT_TIMER` stayed 0).

**What it suggests (G):**
- **The fault is the heartbeat `ld.a.d r3, r17, #42` itself.** The SGX530 forms that load's
  address differently from the SGX545 encoding the image uses, or r17 doesn't hold
  0x0f003000 there. 0x0fd79000 against 0x0f003000 + 42 in some unit is for the microkernel
  session to work out.

**Next:** the microkernel session decodes the effective-address formula. If it's an ISA
difference, it goes into the docs as C and to the clean-room ISA work.
